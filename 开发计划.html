Monster Job32 开发计划

目标：先理解魔灵召唤玩法，再沉淀状态识别、动作执行、任务状态机，最终接入 Agent 执行重复游戏任务。

待开始 进行中 已完成 阻塞

总体架构方向

1. 玩法知识采集 通过截图、模板、状态、动作标注，把真实游戏页面转成结构化知识。
2. 状态识别 多个模板证据合成语义状态，例如 home、battle_running、battle_result。
3. 玩法状态机 用状态、动作、条件、变量、超时和重试表达完整玩法流程。
4. Agent 决策 Agent 只选择白名单语义动作，不直接点击坐标。 
游戏窗口 → 截图 → 状态识别 → 玩法状态机/Agent 决策 → 语义动作 → dm.dll 输入执行 → 游戏窗口

建议的近期最小闭环

  1. 扩展模板 JSON：先加 activity、state、purpose、action_name、expected_next_state。
  2. 用当前游戏主城截图标注 global/home，框出 battle_button。
  3. 手动进入战斗菜单，继续截图并标注 battle_menu。
  4. 沉淀连续战斗所需状态：home、battle_menu、dungeon_select、team_select、battle_running、battle_result。
  5. 实现最小 StateDetector：模板加权、优先级、unknown。
  6. 实现最小 ActionRegistry：click_template + expected_next_state 验证。
  7. 实现连续战斗 3 次的 RuleBasedAgent / ActivityRunner。
