## 前端功能与页面规划

本次规划以参考项目 `frontend/src/App.vue` 的模板制作和 loop_template 页面为依据。新项目保留其分组卡片、截图框选、编辑抽屉、流程列表与运行控制交互，名称从 Template 改为 State；运行目标改为 ADB 安卓设备。本文是页面及接口规划，尚未实现页面改造。

### 页面结构

仅设两个主入口：**State 制作**、**循环流程**。顶部共用设备选择、设备刷新、API/OCR 状态。默认进入 State 制作，无设备时仍可导入 PNG 制作与预览。采用现有 Vue 2 / Element UI，不增加前端框架迁移。

### State 制作：对应原 template 页面

页面由分组导航、State 卡片库、截图工作台组成。编辑在右侧抽屉中完成，保存后更新卡片，不跳出当前截图。

| 原项目交互 | 新项目规划 |
|---|---|
| 全部、未分组、分组卡片与模板数量 | 保留；按业务场景组织 State，支持新建、重命名、复制及删除分组 |
| 图片缩略图、名称、优先级、流程标签 | 保留；文字 State 用候选文案展示，图片 State 展示裁剪图 |
| 选择卡片进入编辑抽屉 | 保留；新增/编辑共用表单，保存、取消、复制、删除均给出明确反馈 |
| 窗口截图、识别区框选、点击区框选 | 截图来源改为选中的 ADB 设备，也可导入 PNG；保留框选与坐标回显。独立点击区需要扩展动作配置，不能直接套用旧桌面坐标 |
| 图片匹配阈值、优先级、动作配置 | 表单编辑已有参数；动作以无动作、点击、安卓按键、滑动及等待为主，不要求用户手写 JSON |
| 同帧后置模板、后置非模板 | 映射为已有 required_states / excluded_states；页面用 State 多选器配置 |
| 成功、结束、兜底等标识 | 使用当前 normal/success/failure/fallback 角色，不照搬语义不同的旧标识 |
| F1～F6 工作台快捷操作 | 所有功能先提供可点击按钮；F1 截图、F2 框选、F4 保存等可保留页面内快捷键，Mac 提供按钮替代。输入框聚焦时不抢占快捷键 |
| 单模板、整组识别执行 | 区分“识别预览”和“执行动作”；预览无输入，命中框、得分与歧义可视化，实际执行必须显式选择设备及确认执行入口 |

文字 State 沿用现有 RapidOCR 能力：多候选文案、exact/contains/fuzzy、置信度与 ROI。图片算法、默认匹配范围和循环选择规则沿用当前版本；本轮不引入 SIFT、YOLO、UIAutomator2 或新的自动识别回退。

### 循环流程：对应原 loop_template 页面

左侧为可筛选的流程卡片列表，右侧为所选流程配置；下方展示运行状态、事件和截图证据。点击参考 State 卡片打开同一编辑抽屉。

- 流程管理：新建、命名、编辑、复制、删除、保存，支持多个流程独立保存。
- State 选择：保留按分组选择和参考卡片预览；保存显式 State ID 集合，避免执行时无意纳入后来新增的 State。
- 参数配置：完成次数、最大轮数、超时、轮间等待、只识别模式；显示当前成功/失败/兜底 State 数量。
- 操作按钮：保存、保存并启动、停止；暂停/继续保留为交互目标，但必须先实现后端协作暂停，不能用前端停止轮询模拟暂停。
- 运行反馈：展示 run_id、状态、停止原因、成功次数、当前命中、近期事件及截图证据；离开页面或刷新后可重新查看所记录的运行。
- 配置预览：保留原配置预览思路，使用新项目 JSON，不引入旧 YAML/state_scripts 执行器。
- 运行期间沿用现有同设备互斥和配置修改限制，避免预览或编辑改变正在执行的配置。

### 现有能力与必要补充

现有 API 已支持设备、截图/导入、裁剪、State 保存列表、单 State 预览、单流程保存、启动、停止及运行记录。当前单页只能作为核心链路验证版，不等同于上述页面已交付。

需要补充的接口和存储：

1. State 分组元数据、复制/删除与引用检查；复制图片时同时处理资源引用，删除分组不能直接误删被流程引用的 State。
2. 多流程列表、按 ID 读写、复制/删除；迁移现有单流程配置为默认流程，不丢失用户配置。
3. 如实现独立点击区，保存匹配框相对坐标并在执行时验证；不能保存网页缩放后的绝对坐标，也不恢复旧的无截图多次点击链。
4. 整组预览、运行列表，以及暂停/继续协作接口。停止仍优先取消并保存结果，不直接移植原项目的进程强杀行为。

这些是保留交互所需的业务支持，不修改图片识别算法。尚未接入的能力不显示为可操作按钮，也不以浏览器本地缓存代替后端保存。

### 实施顺序与验收

1. 先拆出两个页面、共享编辑抽屉和动作表单，接入已有接口。验收：截图/导入→框选→保存→卡片编辑→识别预览→选择 State→保存并启动→停止完整可用，文字 State 功能不回退。
2. 再完成分组和多流程持久化。验收：复制/重命名/删除后刷新仍一致，现有 State 与流程配置完整保留，引用错误可见。
3. 最后完成独立点击区、整组预览、暂停恢复和快捷键等依赖后端补充的交互。验收：暂停期间不发送新动作，恢复不重复已执行动作；框选、命中与 ADB 坐标一致；按钮与快捷键等效。

不移植流程调度、Windows 窗口工具、游戏专用流程、旧图流程引擎、COM/dm 和弃用模块。总览统计仅在主页面有需要时展示，不额外建立门户页面。
