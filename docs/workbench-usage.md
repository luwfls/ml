## State 制作与循环流程

### 启动

一键启动前后端：Mac 双击根目录 `start-macos.command`，或在项目目录执行 `bash ./start.sh`；Windows 双击 `start-windows.cmd`。启动成功后访问 http://127.0.0.1:8765，无需另开前端终端。Ctrl+C 停止服务。

首次启动会创建虚拟环境、安装锁定依赖并构建前端；需要标准 Python 64 位（Intel Mac 为 3.13，其他环境为 3.14）、ADB，以及 Node.js LTS（部署包已有匹配的前端构建时无需 Node）。Intel Mac 使用独立 `.venv-intel` 和 `requirements-macos-intel.txt`；其他环境使用 `.venv`。首次安装需要联网，后续复用已有环境和构建。将 Android platform-tools 解压到项目的 `platform-tools` 目录，或将 adb 加入 PATH；也可指定 `bash ./start.sh --adb "/路径/platform-tools/adb"`。仅调试导入截图并启用 OCR 时用 `bash ./start.sh --no-adb`，无需 ADB。

命令入口支持 `--no-ocr`（仅图片模式）、`--port 8766`、`--ocr-config ocr.local.json`、`--setup-only`（只准备环境）、`--refresh`（重装依赖/重建）。`--no-ocr` 只关闭运行时 OCR，仍安装完整锁定依赖，平台支持要求同下文。Mac 若提示脚本没有执行权限，执行 `chmod +x start-macos.command start.sh`；若系统阻止打开，请在 Finder 中右键打开并按系统提示确认。程序不会自动安装系统 Python/Node/ADB。

Windows 使用根目录 `start-windows.cmd`，部署步骤见 windows-deployment.md。源码前端构建为 `npm ci`、`npm run build`，构建后由后端同时提供页面和 API：http://127.0.0.1:8765。

Mac/Linux 前后端开发分别启动（Intel Mac 请优先使用上述一键启动器，独立环境及兼容说明见 `docs/platform-startup.md`）：

```bash
# 在项目目录中，使用标准 Python 3.14 64 位
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements-tested.txt
.venv/bin/python -m automation --data data --port 8765
```

另一终端在同一目录执行 `npm ci`、`npm run dev`，打开 http://127.0.0.1:5173。前端代理后端 8765；保持两个终端打开，停止时分别 Ctrl+C。

仅验证管理页面可用 `bash ./start-platform.sh`，不安装或加载 OCR。无需 ADB 即可导入 PNG 制作图片 State；文字预览必须启用 OCR，设备截图和执行动作必须安装 ADB 并选择授权设备。Python 3.14 的 ONNX Runtime 1.30.0 macOS wheel 仅提供 arm64；Intel Mac 由启动器选择 Python 3.13 + ONNX Runtime 1.20.1。完整 OCR 模式要求 macOS 14+，详见 `docs/platform-startup.md`。

### 手动多设备任务

先在“循环流程”页面保存编排好的流程，再进入“任务”页面，创建任务、填写名称并关联一个已保存流程。任务 ID 自动生成，保存后可重复手动启动。

点击“手动启动”，多选在线且空闲的 ADB 设备。这里只选择手机/模拟器实例，不选择或自动打开安卓应用；启动前人工将各设备停留在目标业务页面。只识别模式沿用已保存流程配置，实际发送输入动作时需确认。

一次启动为一个批次，每台设备独立生成运行 ID、结果、日志和截图证据。启动结果按设备展示；某台设备离线、被占用或启动失败时，其他设备仍可启动。同一设备不能同时执行两条流程，空闲设备可以在其他设备运行期间继续启动任务。

任务关联的运行记录可打开原运行面板，逐设备暂停、继续或停止。每台设备独立计算完成次数、超时和最大轮数；不合并计数。任务保存在 `data/tasks`，历史运行保存在 `data/runs`，重启服务后保留配置及历史，但不会自动重放未完成运行。已有任务引用的流程需先解除引用才能删除。

多设备共享本机 CPU OCR 引擎，推理沿用已有串行锁；本功能不引入定时调度或多机执行。

### 制作 State

在工作台按 F4 或点击「新增并保存 F4」，打开保存抽屉；确认配置后点击「确认保存 F4」或再次按 F4 保存。输入框内也支持 F4，取消抽屉只返回同屏编辑，不会自动保存。新建 ID 由系统生成，不需要填写，编辑已有 State 保持原 ID。

名称为必填项：为空或只有空格时，保存会直接定位到名称输入框并提示，不发送保存请求，也不提前裁剪生成资源。保存接口返回的其他错误会显示在抽屉内；填写名称后可继续保存。

启用文字匹配后，可点击「添加候选文案」逐条输入、移除文案；任意一个候选匹配即可算文字命中，再按图文「且／或」配置与图片结果组合。

「图片资源」是图片匹配使用的小图模板文件名，不是整张截图。F2 在截图上框出蓝色识别区后，「裁剪识别区」将框内画面生成模板并显示预览；保存时也会自动裁剪新的框选区域，通常无需先点裁剪按钮。它不设置点击位置；点击区使用 F3。

保存 State 时会关联当前完整截图；重新打开 State（包括刷新页面后）会自动显示原图，并恢复识别区与点击区。原图保存在 `data/captures/`，模板保存在 `data/assets/`，State JSON 保存在 `data/states/`。多个 State 可以共享一张完整截图，复制 State 也保留原图关联，图片模板仍独立复制。

旧 State 没有原图记录，无法自动推断对应截图，请导入原图并保存一次建立关联。原图文件已删除时会提示重新导入，不会显示其他 State 的截图；已有模板和配置仍保留。

先建立业务分组，例如“采购收货”。选择安卓设备截图，或导入本地 PNG；框选稳定的识别图案，在截图右侧同屏编辑器填写中文名称、分组和角色后保存（ID 自动生成），窄屏自动上下排列。

图片 State 显示裁剪缩略图，文字 State 显示候选文案。图片与文字可分别勾选，至少启用一种；同时启用时支持「且 AND / 或 OR」。文字支持多候选文案 OR（逐条添加）、精确/包含/模糊匹配和置信度。模糊匹配不要使用过短文案。预览展示匹配框、得分及歧义，仅预览不发送设备输入。

新建 State 默认勾选「仅在识别区内搜索」，搜索范围跟随蓝色识别区；关闭后图片与文字均搜索全图，无需单独圈选 ROI。重新框选识别区后直接保存会替换图片模板，候选文字不变；开关与框选范围随 State 保存，重新打开并导入截图后恢复。旧配置保留原搜索范围。可先关闭范围限制保存纯文字 State。

动作使用表单配置：无动作、点击、返回/主页/确认、滑动及动作后等待。成功和失败 State 仅作为断言，没有输入动作。普通 State 每次识别最多一个输入动作，其后的操作由新截图触发；等待-only 配置仍可保存。图片 State 或图文「且 AND」可设置独立点击区（「或 OR」请使用匹配中心），其位置相对于识别图案保存；匹配时映射回当前截图坐标，并拒绝越界或歧义目标。

条件中的“同时命中”与“同时不能命中”引用其他 State，在同一帧判断。编辑已有配置时保留现有高级参数；本版本不改动识别算法。

单 State 执行使用已保存的配置和设备新截图，点击执行前确认。不要将导入的旧截图当作当前设备画面执行。分组预览无动作，可用于检查同帧条件。

### 配置循环流程

新建流程时只需填写名称，ID 由系统自动生成；列表、选择器及复制弹窗均使用名称。复制流程填写副本名称即可。

「显式 State」为选填，可留空保存、复制并在以后继续配置。运行前需选择参与执行的 State，且至少包含一个成功 State；留空不表示执行全部 State。分组用于快速选择，保存时记录所选集合，后来新增 State 不会自动加入已保存流程。

配置完成次数、最大轮数、超时和轮间等待，先开启“只识别”验证命中；确认识别正确后才开启实际执行。参考 State 卡片会跳转到 State 工作台同屏编辑器。

选择设备，保存并启动。运行面板提供状态、成功次数、事件和截图证据；记录存于 `data/runs`。同一个设备不能同时执行两个流程；运行或暂停期间先停止再修改 State/资源。

暂停是协作暂停，会等待当前有界的截图/识别/动作结束；界面可能先显示“暂停中”。暂停后不发送新动作，恢复保留当前计数与重复动作保护。停止会取消暂停中的任务并保存结果。识别歧义导致的终止状态不能用继续按钮恢复，需要检查配置后重新启动。服务重启后仍能查看记录，未完成的旧运行标记为中断，不自动重放动作。

### 数据与兼容性

运行数据仅保留在本机：`data/`（含 `captures/assets/states/flows/tasks/runs/batches`）整体被 Git 忽略，根目录下同名数据目录及 `logs/` 也忽略。测试用的 `tests/fixtures/` 图片继续入库。Git 同步不会携带本机 State 配置或完整截图，需要迁移时复制并备份整个 `data/`。

清除本机运行数据：先停止服务，再在项目目录执行 `python3 scripts/clean_runtime.py`。此命令会删除默认 `data/` 及根目录 `captures/assets/states/flows/tasks/runs/batches/logs`，包含所有本地 State、流程、任务、截图和运行记录；不删除源码或测试素材。自定义 `--data` 目录不受此命令影响。Git pull 不会自动删除已忽略的本地数据，也不会在每次启动时自动清空配置。

多个流程和分组保存在项目 `data` 目录。升级前建议备份整个 `data`；既有 State 和旧 `flow.json` 保留，旧单流程作为默认流程迁移。复制图片 State 同时复制其图片资源，删除被流程或其他 State 条件引用的 State 会被拒绝；删除分组需先处理其成员，避免无意删除测试资源。

本版本不包含旧项目调度器、Windows 窗口工具、游戏模块或旧 YAML 图流程引擎。Windows/Mac 实机及真实安卓业务端到端仍需现场验收；本地浏览器与替身设备验证记录见 VERIFICATION.md。
